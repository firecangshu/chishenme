## 表单正文（四段式，直接复制）

**1. 团队/个人介绍**

我是一名独立开发者，专注用小而美的 AI 工具解决日常高频小决策。本作品从菜品素材库、决策引擎到 AI 自然语言理解层均由我独立设计与开发，并围绕真实使用反馈持续多轮迭代。

**2. 创意名称＋创意介绍**

作品名《今天到底吃什么呢？》，是一个在浏览器和支付宝内即可直接打开的智能 Web 应用（H5＋决策型 Agent）。灵感来自我自己每天饭点翻十几分钟外卖 App、最后还是不知道吃什么的真实经历——选择困难本质是高信息量下的决策疲劳，用户需要的不是更多选项，而是一个"不把选择抛回来"的决策助手。因此我让用户只需说出忌口和需求，30 秒内得到一道安全、对味、带一点惊喜的具体菜。

**3. 目标用户及痛点**

目标用户是每天要决定工作餐、外卖的上班族和学生，尤其是有忌口、食物过敏或减脂需求的人。他们的痛点有三个：一是选择困难，榜单越翻越纠结；二是忌口零散且关乎安全——忌辣、不吃某类肉、花生/海鲜过敏、素食等需求，普通关键词推荐很容易把含过敏原的菜误推出来；三是轻食人群难以判断每道菜的热量。本产品让用户用点选或一句自然语言说出忌口，系统从结构化菜品库中安全剔除雷区后再随机决策，帮助用户在 30 秒内拿到一道"既合规又符合热量预期"的具体菜，而不是又一份榜单。

**4. 功能介绍**

使用流程：首页选择「吃啥」或「摇一个盲盒」→ 第 1 步用标签点选或一句自然语言描述忌口（可接入自己的大模型做 AI 智能识别）→ 第 2 步选择是否需要轻食 → 得到一张带菜品插画、热量、地域、制作用时、价格和推荐理由的结果卡，可点「换一个」在合规候选池内继续随机。

核心特色：
① 结构化素材库＋安全硬过滤：34 道菜逐一标注辣度、成分标签（猪/牛/羊/鸡、海鲜、花生、乳制品、鸡蛋、大豆、麸质）与素食属性；过敏原等忌口为硬过滤、绝不放宽，并把筛选过程对用户透明展示（"已按 N 项忌口，从 34 道中剔除后剩 M 道，随机为你挑中这道"），安全且可解释。
② AI 感知＋规则决策分层的 Agent 架构：大模型只负责"听懂人话"，把任意口语忌口（如"痛风别来海鲜、奶也不行，还怕辣"）解析为结构化标签，输出经白名单收敛，系统不支持的类别（如高嘌呤）会如实提示而非乱筛；具体剔除与随机由确定性规则引擎执行，兼顾自然语言的灵活与食品安全的确定性，模型无法绕过过敏原硬过滤。AI 自然语言能力为可选的 BYOK（自带密钥）接入，兼容任何 OpenAI 接口的模型（DeepSeek、通义千问、Kimi、本地 Ollama）；出于隐私与安全，默认不内置公共密钥，密钥只保存在用户本机、请求直发模型厂商、不经作者服务器。无需任何密钥即可开箱完整体验标签点选与全流程决策（此时忌口识别由内置同义词规则离线完成），填入自有密钥后即解锁自然语言口语理解，模型调用失败也会自动降级、流程不中断。
③ 双模式与轻食：推荐模式直接给结果，盲盒模式用 1.2 秒"老虎机"旋转制造惊喜；轻食模式在 ≤500kcal 低卡池中随机，兼顾健康与不重样。

技术与数据：前端 React 18＋esbuild 打包，纯静态、零后端，部署于 GitHub Pages，可直接被生活服务场景调用；AI 层走标准 OpenAI 兼容接口；菜品库为自建结构化数据，34 张菜品插画为 AI 生成的统一治愈系画风。实际价值是把"吃什么"这件每天都发生的小事，变成安全、可控、有惊喜的 30 秒决策。

## AI 必要性（对准评审维度，备查不必填）

- **用户价值**：饭点选择是每天 1–3 次的高频真实需求；忌口/过敏是安全相关的硬需求。
- **AI 必要性**：传统外卖/点评只能"给更多选项＋关键词匹配"，做不到两件事——理解任意口语化忌口、并在理解后保证过敏原零穿透。本作品用"大模型理解 + 规则引擎安全决策"的分层同时解决，是传统表单/检索产品难以实现的。
- **责任可信**：过敏原硬过滤不放宽、候选池透明、BYOK 密钥不出本机、内置免责声明、不提供医疗营养确定性结论。
- **生态适配**：纯 URL 即可访问与被调用，无需安装，适配支付宝生活服务与"蚂蚁阿宝"调用场景。

## 评委体验与 BYOK 说明口径（已定：不录视频、不内置公共 Key，只用文字说明）

- **默认打开即完整可用**：标签点选忌口 → 过敏原硬过滤 → 候选池透明 → 随机结果/盲盒/轻食，全流程离线可跑，**评审无需任何 Key**。
- **AI 自然语言理解是可选增强**：在第 1 步「AI 智能识别（选填）」折叠区填入任一 OpenAI 兼容 Key 后，可直接输入口语化忌口；密钥仅存本机 localStorage。
- **为什么不内置公共 Key**：避免公共密钥泄露/被盗刷，请求不经作者服务器、零后端零留存，正是「责任可信」维度的体现，而非功能缺失。
- **评审现场未配 Key 时**：看到的是规则兜底版（功能完整、结果一致）；口语解析能力以上方正文描述与代码仓库 `llmParser.js` 为准。
